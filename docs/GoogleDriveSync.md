# Google Drive Sync

Letter Boxed Cubed can synchronize its portable player data and GUI state through a small Google Apps Script bridge owned by the user. The actual cloud backup is stored as a visible JSON file in a `Letter Boxed Cubed` folder in the user's Google Drive.

## Why a bridge?

LBC runs on `nytimes.com`, which Nathan Burgdorff does not own. Google's OAuth policies require web-app JavaScript origins/redirects to use domains the developer owns or is authorized to use, and Google's browser token model uses short-lived access tokens that eventually require another user-driven authorization gesture. A user-owned Apps Script bridge avoids both problems: Apps Script receives Drive permission once, while LBC talks only to the user's deployed bridge.

## One-time setup

1. Open Google Apps Script and create a new project.
2. Replace the default code with `integrations/google-drive/Code.gs` from this repository.
3. Run `Setup()` once from the Apps Script editor and approve the requested Drive permissions.
4. Copy the `Sync secret` from the execution log.
5. Choose **Deploy > New deployment > Web app**.
6. Set **Execute as** to **Me** and **Who has access** to **Anyone**.
7. Deploy and copy the Web App URL ending in `/exec`.
8. In Letter Boxed Cubed, click **Drive: Setup** and paste the `/exec` URL and sync secret.

The endpoint is technically public because Apps Script must accept LBC's cross-site request, but every request is authenticated with the high-entropy shared secret generated by `Setup()`. LBC stores that secret only in local Tampermonkey storage; it is deliberately excluded from manual exports and cloud payloads.

## Sync behavior

Each sync is read-merge-write:

1. LBC reads the current cloud backup and its revision number.
2. The remote backup is migrated to the current schema if necessary.
3. Remote data is merged into local storage using LBC's normal import merge rules.
4. LBC builds a fresh merged backup and asks the bridge to write it only if the revision has not changed.
5. If another device updated the cloud copy in the meantime, the bridge reports a conflict and LBC retries from the new revision.

Automatic sync is debounced after durable changes such as finding a word, solving a Twofer, adding a custom dictionary word, or changing a portable GUI preference. A startup sync also runs automatically when Drive is configured. The header button can force a manual sync; Shift-click it to reconfigure or disconnect the current browser.

## Merge rules

Monotonic player discoveries are unioned, never replaced:

- Found Words: set union.
- Found Twofers: set union.
- Per-puzzle custom words: set union.
- Custom dictionary: merge by word while preserving honest first-added provenance.
- Puzzle metadata: prefer newer/richer canonical information without removing older non-empty facts.
- Twofer caches: prefer the newer cache version, or the richer cache at the same version.

Portable GUI settings use per-setting timestamps, so changing Animation Speed on one device does not cause an unrelated, newer Hints expand/collapse action on another device to overwrite it.

Physical layout values such as panel width are device-local. They remain in manual disaster-recovery exports but are deliberately omitted from Google Drive sync so a laptop cannot rewrite a desktop monitor's preferred dimensions.

## Backup format

Google Drive sync uses the same versioned `LetterBoxedCubedBackup` payload as manual export/import, wrapped in a tiny cloud envelope containing a protocol version and monotonically increasing revision number. The cloud connection URL and secret are never part of that payload.
